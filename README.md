# بات سیگنال — NewMe Capital

واچ‌لیست را روی تایم‌فریم یک‌ساعته اسکن می‌کند. وقتی قیمت به ستاپِ استراتژی رسید یا
به آن نزدیک شد، برای ادمین تصویرِ تحلیل‌شده و شواهد را می‌فرستد. اگر ادمین تأیید
کند، تحلیل و سیگنال در کانال منتشر می‌شود.

```
اسکن (هر 1h / 4h / 1d) ─► امتیاز ≥ آستانه؟ ─► عکس + شواهد برای ادمین
                                                 │
                         ✅ انتشار ◄─────────────┤
                         │                       └─► ❌ رد
                         ▼
     کانال: ۱) عکس + تحلیل   ۲) سیگنال (ورود، حد ضرر، سه تارگت) در پاسخ به آن
```

## استراتژی

سه شرط کنارِ خطِ روند، روی **کندلِ بسته‌شده‌ی یک‌ساعته**. خطِ روند پایه است و
بدونِ آن امتیاز صفر می‌ماند:

| شرط | امتیاز | جزئیات |
|---|---|---|
| خط روند صعودی | 30 | دو کفِ چرخشیِ ماژور (۶ کندل هر طرف)، هرکدام با واکنشِ ≥ ۲ ATR. از اولین برخورد تا الان هیچ کندلی زیرِ خط بسته نشده. کندلِ فعلی در فاصله‌ی ≤ ۰.۵ ATR از خط است. اگر فقط در حالِ نزدیک شدن است (≤ ۱.۵ ATR)، نصفِ امتیاز را می‌گیرد |
| فیبوناچی 0.618 | 25 | فیبو از کفِ موج (برخوردِ دوم) تا سقفِ بعدش کشیده می‌شود. سطحِ ۰.۶۱۸ باید ≤ ۰.۶ ATR با خط فاصله داشته باشد (تا ۱.۲ ATR نصفِ امتیاز) |
| واگرایی RSI | 25 | بینِ کفِ فعلی و یک کفِ ۸ تا ۶۰ کندل قبل. **معمولی**: قیمت پایین‌تر، RSI بالاتر. **مخفی**: قیمت بالاتر، RSI پایین‌تر، که روی خطِ روندِ صعودی رایج‌تر است |
| کندلِ برگشتی | 20 × قدرت | روی یکی از ۲ کندلِ آخر: پوشا و ستاره‌ی صبحگاهی ×1.0، چکش ×0.9، نفوذی ×0.85، انبرک ×0.75، هارامی و دوجی ×0.6 |

**هشدار** از امتیازِ ۷۰ (قابلِ تغییر). یعنی دست‌کم خط به‌اضافه‌ی دو شرطِ دیگر.
اگر هر چهار شرط کامل باشد، پیام «ستاپِ کامل» می‌گوید؛ وگرنه «نزدیک به ستاپ».

**پلن:**
- ورود: قیمتِ بسته‌شدنِ کندل.
- حد ضرر: زیرِ پایین‌ترینِ کفِ برخورد یا زیرِ خط، هرکدام پایین‌تر، به‌اضافه‌ی ۰.۵ ATR فاصله.
- تارگت‌ها: سقفِ موج، و اکستنشنِ ۱.۲۷۲ و ۱.۶۱۸.
- ابطال: بسته شدنِ کندلِ یک‌ساعته زیرِ خط.

⚠️ متنِ استراتژی «0.168» نوشته شده بود. سطحِ استانداردِ فیبوناچی **0.618** است و
همان پیاده شد. اگر واقعاً سطحِ دیگری منظور است، فقط `strategy.fib.level` را در
`config/default.json` عوض کن.

همه‌ی عددهای بالا در `config/default.json` تنظیم‌پذیرند. فروش (`/direction both`)
با همان منطق روی قیمتِ قرینه اجرا می‌شود.

## بعد از هشدار

**✏️ ویرایش پیش از انتشار.** زیرِ هر هشدار دکمه‌ی ویرایش هست. با آن می‌شود ورود، حد ضرر یا هر تارگت را عوض یا حذف کرد، و یک یادداشتِ تحلیل اضافه کرد که زیرِ تحلیل در کانال می‌آید.
- R:R با هر تغییر دوباره حساب می‌شود.
- پلنِ نامعتبر رد می‌شود، مثلاً حد ضرر بالای ورود در خرید.
- چارت با سطوحِ تازه دوباره کشیده می‌شود.
- «👁 پیش‌نمایش» پست را پیش از رفتن به کانال نشان می‌دهد.

**📈 پیگیریِ خودکار.** بات قیمتِ هر سیگنالِ منتشرشده را دنبال می‌کند.
- **منبع:** کندل‌های ۵ دقیقه‌ای، هر ۱۰ دقیقه، از همان صرافی که سیگنال از آن آمده.
- **اعلام:** تارگت، حد ضرر، برگشت به ورود و پایانِ زمان در کانال، در جوابِ همان پیامِ سیگنال اعلام می‌شوند. به ادمین‌ها هم خبر داده می‌شود.
- **مدیریت:** همان است که پیام می‌گوید: سهمِ مساوی در هر تارگت، و بعد از تارگتِ ۱ حد ضرر روی ورود.
- **پایانِ زمان:** بعد از `maxHoldHours` (پیش‌فرض ۱۲۰ ساعت)، سیگنال با قیمتِ همان لحظه بسته می‌شود.

⚠️ پیگیری و کارنامه در `DATA_DIR` ذخیره می‌شوند. بدونِ Volume در ریل‌وی، با هر دیپلوی پاک می‌شوند.

**👀 هشدارِ نزدیک شدن.** وقتی قیمت به خط روند نزدیک می‌شود (≤ ۱.۵ ATR)، یک پیامِ کوتاه با دکمه‌ی چارت فقط برای ادمین‌ها می‌آید. برای هر ستاپ یک بار. از تنظیمات خاموش می‌شود.

## داده

اولویت: **LBank ← Binance اسپات ← MEXC ← Gate ← Bitget ← Binance فیوچرز**. اگر صرافیِ اول نماد را نداشت
یا کمتر از ۱۵۰ کندل داد، سراغِ بعدی می‌رود. وضعیتِ فعلیِ واچ‌لیست:

| نماد | منبع |
|---|---|
| BTC, SOL, AVAX, AAVE, HYPE, NEAR | LBank |
| XAUUSD | LBank ‏`XAUT/USDT` (توکنِ طلا که قیمتِ اونسِ طلا را دنبال می‌کند) |
| MAGMA | LBank و Binance اسپات ندارند ← MEXC |

نمادی که نگاشتِ خاص لازم دارد، مثلِ طلا، در `config/default.json` تعریف می‌شود.
بقیه با `/add` اضافه می‌شوند.

## پنل

`/panel` یک پیام باز می‌کند. با هر دکمه همان پیام عوض می‌شود و پیامِ تازه نمی‌آید:

```
🏠 خانه ── 🔎 اسکنِ همین الان
        ├─ 📈 کارنامه ── سیگنال‌های باز و بسته، درصدِ موفقیت، جمعِ R
        ├─ 📊 نتایج ─── هر ارز ─── 🖼 تحلیل روی چارت · 🔄 تحلیلِ دوباره · 🗑 حذف
        ├─ 📋 واچ‌لیست ─ ➕ افزودن (نام را تایپ کن)
        ├─ 🧠 استراتژی ─ هر شرط ─── روشن/خاموش · الزامی/اختیاری · وزن · پارامترها
        │              ├─ 📐 پلنِ معامله · 🎯 آستانه
        │              └─ ♻️ همه به پیش‌فرض
        ├─ ⚙️ تنظیمات ── فاصله‌ی اسکن · تایم‌فریم · جهت · آستانه
        ├─ 🔔 در انتظارِ تأیید
        └─ 👥 ادمین‌ها ── ➕ افزودن (شناسه یا فوروارد) · 🗑 حذف
```

- **نتایج:** برای هر ارز می‌گوید کجاست و چرا، مثلاً «خط 2.7 ATR پایین‌تر از قیمت است» یا «روی خط، ولی شرط‌ها کامل نیست».
- **تحلیل روی چارت:** هر وقت بخواهی، برای هر ارز. اگر پلنِ معامله داشته باشد، دکمه‌ی انتشار هم دارد.
- **عدد دادنِ مستقیم:** هر پارامتر `− / +` دارد و «نوشتنِ مقدارِ دلخواه».
- **ذخیره:** تغییرها در `settings.json` ذخیره می‌شوند. فقط مقدارهایی که با پیش‌فرض فرق دارند نگه داشته می‌شوند.
- **شرط‌های اضافه:** فیلترِ روند (EMA) و تأییدِ حجم، پیش‌فرض خاموش‌اند و از پنل روشن می‌شوند. «الزامی» یعنی اگر آن شرط برقرار نباشد هشدار نمی‌آید، با هر امتیازی.
- **امتیاز:** جمعِ وزنِ شرط‌های برقرار تقسیم بر جمعِ وزنِ شرط‌های روشن، از ۱۰۰.

**ادمین‌ها:** کسانی که در `ADMIN_IDS` ِ ریل‌وی هستند «مالک»اند. از پنل حذف نمی‌شوند و فقط آن‌ها می‌توانند ادمین اضافه یا حذف کنند. برای افزودن، شناسه‌ی عددیِ آن شخص را بفرست (خودش با `/id` می‌گیرد) یا یک پیام از او را فوروارد کن. ادمینِ تازه باید یک بار بات را `/start` کند تا هشدارها به او برسد.

دستورهای متنی هم هست: `/scan` و `/scan SOL` و `/id`.

## راه‌اندازی

```bash
npm install
cp .env.example .env      # BOT_TOKEN، ADMIN_IDS، CHANNEL_ID
npm test                  # بدون شبکه
npm run scan -- --charts  # اسکنِ واقعی بدونِ تلگرام؛ تصویرها در out/
npm start
```

بات باید **ادمینِ کانال** باشد و اجازه‌ی ارسالِ پیام داشته باشد.

## Railway

۱. **Variables:** `BOT_TOKEN`، `ADMIN_IDS`، `CHANNEL_ID`.
۲. **Volume** با mount path ‏`/data`، و متغیرِ `DATA_DIR=/data`. بدونِ آن، دیسک با هر
   دیپلوی پاک می‌شود. واچ‌لیستی که با `/add` ساخته‌ای برمی‌گردد به پیش‌فرض، و
   دکمه‌ی هشدارهای قبلی «پیدا نشد» جواب می‌دهد.
۳. **Region: اروپا** (Settings ← Deploy ← Region). سرورِ آمریکا را Binance
   فیوچرز با خطای 451 رد می‌کند و MAGMA داده نمی‌گیرد. اسپات از آینه‌ی
   `data-api.binance.vision` می‌آید و محدودیت ندارد.
۴. **Replicas = 1.** تلگرام به هر بات فقط یک polling می‌دهد. دو نمونه یعنی خطای
   409. بات خطای 409 را صبر می‌کند و کرش نمی‌کند، ولی پیام‌ها بینِ دو نمونه پخش
   می‌شوند.
۵. دامنه‌ی عمومی و health check لازم نیست. این سرویس worker است و پورتی باز
   نمی‌کند.

اگر یکی از متغیرها خالی یا غلط باشد، بات در لاگ دقیقاً می‌گوید کدام، و با کدِ ۱
خارج می‌شود.

## بک‌تست — آیا استراتژی جواب می‌دهد؟

```bash
npm run backtest                                   # کلِ واچ‌لیست، ~۷۰ روزِ اخیر
npm run backtest -- NEAR --charts                  # + تصویرِ لحظه‌ی هر سیگنال در out/backtest
npm run backtest -- --threshold 90                 # فقط ستاپ‌های تقریباً کامل
npm run backtest -- --set strategy.plan.slBufferAtr=1.0   # یک پارامتر فقط برای این اجرا
```

استراتژی روی گذشته کندل‌به‌کندل اجرا می‌شود و در هر لحظه فقط داده‌ی همان لحظه را
می‌بیند. بعد بررسی می‌کند که قیمت اول به کدام رسیده: تارگت یا حد ضرر. مدیریت مثلِ
پیامِ سیگنال است: یک‌سوم در هر تارگت و بعد از تارگتِ اول حد ضرر روی ورود. اگر حد ضرر
و تارگت هر دو در یک کندل لمس شوند، بدبینانه حد ضرر حساب می‌شود.
